ที่มาและวัตถุประสงค์
───────────────────────────────────────────────────────────────
ฝ่าย HR ต้องการพัฒนา Chatbot เพื่อให้พนักงานสามารถสอบถามเรื่อง
นโยบายและข้อปฏิบัติด้าน HR ได้โดยตรง โดยไม่ต้องโทรหาเจ้าหน้าที่
ทุกครั้ง ในการประชุมครั้งนี้จึงมีเป้าหมายเพื่อกำหนด Requirement
เบื้องต้นสำหรับการพัฒนาในรูปแบบ Proof of Concept (PoC) ก่อน
เปิดใช้งานจริงในอนาคต


════════════════════════════════════════════════════════════════
สรุปสาระสำคัญจากการประชุม
════════════════════════════════════════════════════════════════


1. ชื่อและเป้าหมายของระบบ
───────────────────────────────────────────────────────────────
ที่ประชุมตกลงตั้งชื่อ Chatbot ว่า "MOF HR แชท" เนื่องจากสั้น
กระชับ จดจำง่าย และสื่อถึงความเป็นของกระทรวงการคลังอย่างชัดเจน

เป้าหมายหลักของ Phase แรกนี้คือทดสอบการใช้งานภายในทีม HR เท่านั้น
ยังไม่เปิดให้บุคลากรทั่วไปใช้ ขอให้ระบบทำงานได้ก่อน แล้วค่อยขยาย
ขอบเขตในระยะถัดไป


2. กลุ่มผู้ใช้และขนาดระบบ
───────────────────────────────────────────────────────────────
Phase นี้มีผู้ใช้เพียง 1–2 คนเท่านั้น ซึ่งเป็นเจ้าหน้าที่ภายใน
ทีม HR ที่ประชุมจึงเห็นตรงกันว่าไม่จำเป็นต้องออกแบบรองรับ Scale
ขนาดใหญ่ในขั้นนี้ ขอให้เน้นที่ความถูกต้องของเนื้อหาและความง่าย
ในการทดสอบก่อน


3. Tech Stack และการ Deploy
───────────────────────────────────────────────────────────────
ทีม IT แจ้งว่าถนัด JavaScript มากที่สุด และสำหรับ PoC นี้การ Build
ด้วย JavaScript เพียง Service เดียวก็เพียงพอแล้ว ไม่จำเป็นต้องแยก
Frontend/Backend ให้ซับซ้อน

ในส่วนของ Deployment ที่ประชุมเห็นพ้องกันว่าให้ Run Locally
บนเครื่องของทีมก่อนได้เลย ยังไม่ต้อง Deploy ขึ้น Cloud ในขั้นนี้


4. Chat History
───────────────────────────────────────────────────────────────
ที่ประชุมหารือเรื่องการจำบทสนทนา โดยเจ้าหน้าที่ HR ต้องการให้ Bot
สามารถคุยต่อเนื่องได้บ้าง ไม่ใช่ตอบแบบ One-shot ตลอด

ข้อตกลงสุดท้าย: จำ Chat History ย้อนหลัง 5 ครั้งล่าสุด (5 Turns)
เท่านั้น ใช้ Sliding Window แบบง่าย ไม่ต้องมีระบบ Long-term Memory
หรือ Database สำหรับเก็บประวัติการสนทนา


5. Knowledge Base และเอกสาร HR
───────────────────────────────────────────────────────────────
Bot จะตอบคำถามจากเอกสารนโยบาย HR ของกระทรวงฯ ได้แก่
ระเบียบการลา สวัสดิการ ขั้นตอนการขอเอกสารต่างๆ เป็นต้น

สำหรับ Phase นี้ขอเริ่มต้นด้วยเอกสารเพียง 5 หน้าก่อน เพื่อให้
การทดสอบทำได้รวดเร็วและควบคุมขอบเขตได้ง่าย ค่อยขยายเพิ่มในภายหลัง


6. การจัดการ Knowledge — ไม่ต้องใช้ Vector Database
───────────────────────────────────────────────────────────────
ธนพลสอบถามว่าจำเป็นต้องใช้ Vector Database อย่าง Pinecone หรือ
Azure AI Search ไหม พิมพ์ชนกชี้แจงว่าไม่จำเป็นสำหรับขนาดนี้

ข้อตกลง: ใช้ File Search Tool ที่มีอยู่ใน Azure AI Foundry ได้เลย
เพียงแค่ Upload ไฟล์เข้าไปก็สามารถใช้งานได้ทันที ลดความซับซ้อน
ด้าน Infrastructure ลงได้มาก


7. UI Design — Theme และรูปแบบ
───────────────────────────────────────────────────────────────
ที่ประชุมตกลงว่า Theme ของ "MOF HR แชท" จะใช้สีน้ำเงินและสีขาว
ดีไซน์ Clean เรียบง่าย ไม่รกตา เหมาะกับบริบทของหน่วยงานราชการ


8. ภาษาและสไตล์การตอบ
───────────────────────────────────────────────────────────────
Bot จะตอบเป็นภาษาไทย แต่ไม่ต้องเป็นทางการ 100% ให้มีความเป็น
กันเองแบบไทยๆ เพื่อให้พนักงานรู้สึกสบายใจที่จะถาม และไม่รู้สึก
ว่ากำลังคุยกับระบบที่เย็นชา


9. Disclaimer
───────────────────────────────────────────────────────────────
นภัสสรเสนอให้มี Disclaimer แสดงบน UI ชัดเจนว่า AI อาจตอบผิดพลาด
ได้ เพื่อให้ผู้ใช้ยังคง Verify ข้อมูลกับเจ้าหน้าที่ HR จริงๆ อีกที

ข้อความ Disclaimer ที่ตกลง:
"ข้อมูลจาก AI อาจมีความคลาดเคลื่อน กรุณาตรวจสอบกับฝ่าย HR โดยตรง"
จะแสดงไว้ที่ด้านล่างของหน้า Chat อย่างถาวร


10. การยืนยันตัวตนกับ Azure — ใช้ API Key เท่านั้น
───────────────────────────────────────────────────────────────
พิมพ์ชนกหยิบยกประเด็นเรื่องการ Authenticate กับ Azure AI Foundry
ขึ้นมาหารือ เนื่องจากมีตัวเลือกสองแบบหลักคือ

  (ก) Microsoft Entra ID (DefaultAzureCredential / az login)
  (ข) API Key ผ่าน FOUNDRY_API_KEY ใน .env

ที่ประชุมมีมติชัดเจนว่า: ใช้ API Key (ตัวเลือก ข) เท่านั้น
สำหรับ Workshop ครั้งนี้ ด้วยเหตุผลหลักดังนี้

  • เวลาเตรียมงานมีจำกัด — การตั้งค่า Entra ID ต้องการ
    สิทธิ์ระดับ Tenant Admin และขั้นตอน Consent ที่ใช้เวลา
    ไม่เหมาะกับบริบท Workshop ที่ต้องเริ่มได้ทันที

  • ผู้เข้าร่วม Workshop อาจไม่มี az CLI หรือยังไม่ได้ Login
    การแจก API Key ทำให้ทุกคนเริ่มต้นได้เลยโดยไม่ต้อง
    ติดตั้งเพิ่มเติม

  • สำหรับ PoC ขนาดเล็กที่รัน Locally และมีผู้ใช้เพียง
    1–2 คน ความเสี่ยงด้านความปลอดภัยอยู่ในระดับที่ยอมรับได้

ข้อตกลง: ทุก Example และ Application ในโปรเจกต์นี้จะ Authenticate
ด้วย API Key ผ่าน Header `api-key` เท่านั้น ห้ามใช้
DefaultAzureCredential หรือ Token-based Auth ใดๆ ทั้งสิ้น
เพื่อให้ผู้เข้าร่วมทุกคนสามารถรันได้ทันทีโดยไม่ติดขัด
